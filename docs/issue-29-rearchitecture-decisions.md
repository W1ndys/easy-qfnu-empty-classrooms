# Issue #29 新架构已确认需求与设计决策

> 状态：已确认至 Q171。本文仅记录已经确认的需求、事实和决策；未决事项单列，不作为默认实现。

## 1. 目标与边界

- 将在线查询从“用户请求实时访问教务系统”改为“本地采集、GitHub 发布、Vercel Serverless 查询”。
- 公开查询链路不再访问 CAS 或教务系统，不持有教师账号、密码、Cookie 或 Token。
- 本地采集器定期读取教务系统，生成仅包含白名单范围的脱敏快照。
- 快照提交到 GitHub 后触发 Vercel 自动部署；不再要求自建公网服务器。
- 不迁移旧 Docker、Gin、PostgreSQL、查询统计、公告、管理员登录和管理后台。
- 第一版不采集课程、教师、申请人、单双周等占用详情，只保存教室状态。
- 投票形式不属于系统开发范围。白名单统计完成后，由维护者手动编辑配置文件。

## 2. 仓库与部署

- 当前仓库改名为 `easy-qfnu-kjs-legacy`，README 明确标注旧版并归档。
- 新架构建立新的私有仓库并使用正式名称 `easy-qfnu-kjs`，不使用永久性的 `v2` 名称。
- Vercel 连接新的私有 GitHub 仓库，GitHub 主分支完整提交触发自动部署。
- 现有业务域名切换到 Vercel；Vercel 自动分配域名作为备用。
- 旧系统继续运行，直到新仓库完成采集、Vercel 预览、生产验收和业务域名切换；稳定观察后再归档旧仓库。
- Vercel 从仓库根目录构建。
- 建议目录：

```text
easy-qfnu-kjs/
├── api/                    # TypeScript Vercel Serverless Functions
│   └── v1/
├── data/                   # 构建时打包的非公开快照源
├── cmd/
│   └── collector/          # 本地 Go 采集器
├── config/
│   └── rooms.json          # 人工维护的公开分组白名单
├── web/                    # Vue 3 + Vite + Vant 4 前端
├── go.mod
├── package.json
└── vercel.json
```

- `api/` 只放函数；快照不放入 `api/`、`api/_data/` 或 `public/`。
- `_data` 只是命名，不是安全边界。
- `data/` 只由 Serverless 函数在构建时显式导入，不配置静态路由。
- 统一文件布局：`data/manifest.json`、`data/terms/<term>/weeks/week-02.json`、`config/rooms.json`（人工白名单）、`schemas/`（snapshot、manifest、config 三份 JSON Schema，文件名含主版本号）。
- 交付文档：README（架构与快速开始）、`docs/operations.md`（cron、publish、验收、回滚、Git 归档、飞书告警配置）、`docs/upstream.md`（教务接口与解析契约摘要，不含敏感内容）；旧仓库 README 标注“已归档，迁移至新仓库”。
- 浏览器只能通过 Serverless API 查询，不能直接访问快照文件。
- Vercel API 使用 TypeScript/Node.js Runtime，不使用 Edge 或 Go Runtime。
- API 是公开只读服务，不要求用户登录；默认同源调用，不开放通配 CORS，且不把 CORS 当作鉴权。
- Vercel 使用单项目仓库根构建：构建、`web/` 输出目录、`api` 函数、`includeFiles`、rewrites 全部写入 `vercel.json` 入库，不依赖控制台手工配置。
- Vercel 函数区域在 `vercel.json` 的 `functions.regions` 固定为香港 `hkg1`（候选 `sin1`），保持单区域；首次实测延迟后允许调整。
- 业务域名保留现有 DNS 服务商，用 CNAME 指向 Vercel 并由 Vercel 签发 TLS；不迁移域名 NS。
- 上线顺序固定为：开发分支 Vercel 预览验收 → `main` 生产部署并完成生产验收 → CNAME 切换指向 Vercel；旧 Docker 服务保持运行作为回退，稳定观察后再归档旧仓库。
- SPA 使用 Vue Router History 模式：`vercel.json` 把所有非 `/api/*`、非静态资源路径 rewrite 到 `/index.html`，404 由前端路由渲染；未知 `/api/*` 路径仍返回 RFC 9457 `application/problem+json` 的 404。

## 3. 本地采集器

- 采集器使用 Go，入口位于 `cmd/collector/`，复用或迁移现有 `pkg/cas` 登录能力和 HTML 解析逻辑。
- 由本地 cron 或 systemd timer 定期执行，同时保留手动执行命令。
- 使用锁文件或 `flock` 防止采集任务重叠；任务应有总超时，超时后允许后续任务接管。
- cron 直接运行统一维护的开发目录（即同一 clone），不单独准备专用工作目录；采集器只负责修改生成数据和 manifest，其他改动仍按正常提交流程管理。
- 调度使用 systemd user timer（`OnCalendar=*-*-* 04:10:00 Asia/Shanghai`），失败记录到 journald，便于 `systemctl --user` 管理。
- 教师账号、密码等通过环境变量或 `.env` 提供；`.env` 必须被 Git 忽略，秘密不得提交到 GitHub 或进入 Vercel。
- 验证码识别完全使用本地离线方式，不做任何网络 OCR 服务：`.env.example` 提供 `OCR_CMD`（默认 `scripts/ocr_ddddocr.py`，Python `ddddocr`，支持任意读图片路径/stdin 并输出文本的本地命令）；`OCR_URL` 及 ddddocr+Flask 方案废弃。
- 新仓库提供 `.env.example`：`QFNU_USERNAME`、`QFNU_PASSWORD`、`OCR_CMD`，新增可选的 `FEISHU_WEBHOOK_URL`、`FEISHU_WEBHOOK_SECRET`；采集器只从开发目录读取 `.env`。
- GitHub 认证和仓库操作使用已登录的 `gh` CLI；不在配置中保存 PAT。
- 一轮目标周次全部采集、过滤、校验成功后，统一生成一次 Git 提交并推送，避免一次采集触发多次 Vercel 部署。
- 采集器提供 `collect`、`validate`、`publish`、`run` 子命令；`run` 执行完整 cron 流程，且支持 `--dry-run`。
- `collect` 只生成候选快照，`validate` 只校验候选数据，`publish` 负责提交并验证部署，避免手动操作误发布。
- 自动发布在全部校验成功后直接提交并推送 `main`，不创建需要人工合并的定时 PR。
- `publish` 前校验工作区相对远端只存在采集器生成的预期文件变更；发现其他未提交或未推送改动时终止本轮并发送飞书告警，绝不自动 stash 或丢弃用户改动。
- `collect` 的候选快照先写入仓库外的系统临时目录（或被 Git 忽略的暂存目录），`validate` 全部通过后才复制进 `data/` 并进入提交流程；校验失败不污染工作树。
- 自动提交信息统一使用前缀化约定：日常发布 `data: snapshot <term> release <release_id>`、学期切换 `data: term switch <term>`；自动提交范围严格限定为生成数据与 manifest。
- 锁等待策略：`flock` 最多等待 5 分钟，超时则本轮放弃并记录告警；绝不强制终止正在运行的任务。
- 结构化日志写入开发目录下被 Git 忽略的 `logs/collector.log`（每行 JSON），同时保留 stdout/stderr；日志按天滚动，最多保留 30 天。

## 4. 已验证的上游事实

- 全量接口：`POST /jsxsd/kbxx/jsjy_query2`。
- `jsmc_mh` 留空时，单周、星期 1—7、全天查询实测返回：
  - HTTP 200；
  - 2079 条房间记录；
  - 约 9.41 MB HTML；
  - 每行 35 个状态格，即 7 天 × 5 个大节；
  - 每次约 1 秒量级。
- 5 个大节覆盖 12 个小节：

```text
0102    → 01、02
030405  → 03、04、05
0607    → 06、07
0809    → 08、09
101112  → 10、11、12
```

- 已确认业务不变量：同一大节内的小节状态一致。因此允许把 5 个大节状态展开成 12 个小节状态。
- 全学期范围请求返回聚合结果，不能恢复每周独立状态；必须按周请求。
- 若学期有 20 周，完整初始化约需 20 次主查询：每周一次全校、全星期、全天查询。
- `jsmc_mh` 会在上游真实过滤响应，但逐楼请求会增加请求次数、引入模糊匹配重叠和遗漏风险。
- 最终采集路线：每周全量请求一次，仅在采集器内存中按白名单过滤，只发布过滤后的数据；不持久化、不上传全量原始 HTML 或全量房间状态。
- 当前周次页面：`GET /jsxsd/framework/jsMain_new.jsp?t1=1`。已登录后返回当前教学周和总周数；非教学周返回相应提示。
- 当前学期来自默认空教室查询页 `GET /jsxsd/kbxx/jsjy_query`。
- 这两个页面只由已登录的本地采集器使用，浏览器和 Vercel 不直接访问。

## 5. 白名单、查询分组与房间身份

- 不建立覆盖全校的官方建筑目录，不要求 `building_id/building_name` 主数据。
- 房间在每周快照中同等级平铺，不按楼拆文件或嵌套；每个房间附一个查询用 `group_id`，供前端下拉框和 API 筛选。
- 查询分组是人工白名单和产品筛选维度，不冒充教务系统官方建筑主数据。
- 白名单由维护者根据历史查询统计和外部投票结果人工确认，并编辑采集器配置文件。
- 分组 ID 使用人工指定且长期稳定的 ASCII kebab-case；修改显示名称不改变 ID。
- 每个分组支持 `include_prefixes`、`include_exact_names`、`exclude_prefixes` 和 `exclude_exact_names`，不支持正则表达式：

```json
{
  "version": 1,
  "groups": [
    {
      "id": "zong-he-jiao-xue-lou",
      "name": "综合教学楼",
      "enabled": true,
      "order": 10,
      "include_prefixes": ["综合教学楼"],
      "include_exact_names": [],
      "exclude_prefixes": [],
      "exclude_exact_names": []
    }
  ]
}
```

- 匹配顺序固定为：标准化名称 → 应用排除规则 → 应用精确包含和前缀包含 → 统计命中的启用分组。
- 每个公开房间必须且只能属于一个启用分组；未匹配房间不发布；同时匹配多个分组时采集失败，禁止按配置顺序静默裁决。
- `文史楼…` 只命中前缀 `文史楼`，`老文史楼…` 只命中前缀 `老文史楼`；前缀匹配不会把二者混在一起。
- 最终按 `jsbh` 去重；`jsbh` 是房间唯一身份，显示名称允许重复，绝不能用名称作主键。
- 已启用分组若匹配不到任何房间，本轮发布失败；禁止自动扩大匹配范围。
- manifest 分组优先按配置中的显式 `order` 升序排列；未设置或相同时再按显示名称自然排序。
- `enabled: false` 的分组不写入新快照或 manifest，旧 `group_id` 不保留隐藏查询入口；启停分组属于配置版本变化。
- manifest 由同一白名单配置生成公开分组列表，前端和 API 不维护第二份硬编码名单。

## 6. 房间名称规范化

- 2079/2079 条已探测房间名称都带数字容量片段。
- 名称规范化顺序固定：先 Unicode NFKC → 反复删除形如 `(n/N)` 或 `（n/N）` 的纯数字容量片段（半角、全角括号都允许）→ 压缩并清理首尾空格；其余括号与后缀一律保留。
- 保留位置、方向、校区等其他括号和后缀。
- 不保存独立容量字段，也不在公开名称中保留容量。
- 示例：

```text
F126(90/0)                         → F126
篮球馆（东）(25/0)                 → 篮球馆（东）
射艺场地（西田径场以西）(40/40)    → 射艺场地（西田径场以西）
```

- 标准化后仍存在同名不同 `jsbh` 的房间；它们继续作为不同房间保存。

## 7. 采集范围与刷新策略

- 首次初始化按当前学期的全部教学周逐周采集。
- 日常任务在北京时间每天 `04:10` 运行：普通日期刷新当前周和未来 4 周；周日刷新当前学期全部周次。
- 当前周和未来 4 周距最近成功采集超过 36 小时标记为 `stale`；其余周次超过 8 天标记为 `stale`。
- 单次网络请求最多尝试 3 次；CAS 登录最多执行 2 轮；整轮任务总时限 15 分钟；结构校验失败不重试；禁止无限重试。
- 学期字符串变化后自动切换新学期，但必须先成功采集并校验至少当前周数据。
- 新学期首次成功发布的同一提交内删除旧学期 `data/terms/<旧学期>/` 目录并写入新学期目录；Git 历史保留回滚能力，不允许两学期数据长期并存。
- 寒暑假或非教学周时 cron 继续每日运行，但只更新本地上下文并跳过采集发布；恢复教学周后自动切换；常规“不在教学周历内”状态不触发飞书告警。
- 新学期切换时当前周必须采集成功；其他成功周一起发布，失败周暂不列为可用，由后续任务继续补齐。
- manifest 只向公开查询暴露每周期望状态 `fresh | stale | missing`、时间和稳定错误码；完整错误只在本地日志和飞书通知中保留。
- 周快照 JSON 使用两空格缩进、稳定字段顺序、稳定房间顺序并保持换行结尾，便于 Git diff 和人工检查。
- 采集时按教学周顺序逐个请求，两次请求之间使用 `0.5—2` 秒随机间隔；不并发打教务系统。
- HTML 解析测试只使用人工脱敏的最小 fixture，保留表头、房间行、状态格和异常页面特征；原始完整页面和会话内容不进入 Git。
- 前端分组选择使用可搜索下拉框：显示配置的显示名称，值绑定稳定 `group_id`，不允许提交任意文本。
- 节次参数只接受两位字符串 `01..12`，且要求 `start_node <= end_node`；不支持自由格式。
- 新学期切换不要求人工确认，也不把新学期写进旧学期目录。
- 在线 API 只公开当前学期；历史学期仅保留在 Git 历史或归档中，不作为正式查询能力。
- 白名单配置版本变化时强制重新采集当前学期全部周次，全部通过后才发布新 manifest；不允许不同周使用不同分组范围。

## 8. 校验、失败保护与发布原子性

- HTTP 200 不是充分成功条件。发布前至少检查：
  - 未返回登录页、非法访问页或错误页；
  - 目标表格存在；
  - 星期和大节结构符合预期；
  - 节次块必须为预期的 5 个大节 `tdvalue` 集合；遇到作息调整、新增块或未知组合时阻断发布并发送飞书告警，人工确认后才升级解析规则与 Schema；
  - 房间数量处于合理范围；
  - 每个启用分组都有匹配结果；
  - `jsbh` 非空且按 ID 去重；
  - 所有状态码均已知；
  - JSON schema 和引用关系完整。
- 仓库内保存正式 JSON Schema 作为 Go 采集器和 TypeScript API 的共同数据契约；采集完成和 Vercel 构建都必须用同一 Schema 校验，两端仍保留各自静态类型。
- 每次部署生成唯一的整体 `release_id`；每个新采集的周快照生成独立 `snapshot_id`。manifest 为每周记录 `snapshot_id`、文件 SHA-256、最近成功时间和最近尝试结果；周文件保存自身 `snapshot_id`，不强制未刷新的旧周重写整体版本号。提交前和 Vercel 构建时逐一验证。
- 已启用分组匹配结果归零时直接失败；与上一成功版本相比，房间数量变化超过 20% 时阻止发布并要求检查；白名单配置版本变化时重新建立数量基线。
- 未知状态、登录页、Schema 变化等全局异常会阻止整轮发布，不切换公开 manifest。
- 多周日常刷新中仅个别周失败时，成功周使用新快照，失败周保留上一版完整快照；manifest 记录该周最近失败并标记 `stale`。禁止发布任何周内不完整数据。
- 候选发布目录由成功的新周快照和失败周的旧完整快照共同组成；整个候选版本通过 Schema、哈希和引用校验后，一次性提交周文件与 manifest。
- 一次 Git 提交代表一个完整部署版本，Vercel 只构建完整快照。
- `git push` 成功不代表发布成功。发布验收参数：每 15 秒检查一次 GitHub 提交检查状态，上限 10 分钟；构建完成后每 10 秒轮询生产域名 manifest 直到 `release_id` 匹配，上限 5 分钟；随后执行一条样例查询；任一环节超时或失败即发送飞书告警。
- 验收样例查询固定为：manifest 第一个启用分组 + 当前周 + 当天星期 + `01—12`，要求 HTTP 200、响应通过 JSON Schema 校验且 `rooms` 为数组。
- 生产验收失败时保留 Vercel 当前生产部署不动，本轮终止并告警；是否回滚由人工决定，不自动回滚。
- 测试执行位置：开发时本地运行 Go 与 TypeScript 测试；不使用 GitHub Actions，改为本地开发环境的统一校验 skill（`easy-qfnu-kjs-local-ci`）作为提交前 CI；cron 的 `collect`/`run` 不重跑整套测试，发布校验以 Schema、哈希和引用完整性为准。
- 工作树只保留当前学期数据。保留所有成功发布提交，不自动 force-push 或重写主分支历史；Git 打包后仓库体积达到 500 MB 时发送告警，达到 1 GB 时阻止自动发布并要求人工归档。
- 达到 1 GB 后只执行人工归档：先创建私有镜像备份和学期归档包，再使用 `git filter-repo` 删除旧学期 `data/` 历史；完成核验后才 force-push。该流程不得进入 cron。
- Vercel 查询层使用单个 `/api/v1/*` Node.js 函数承载四个资源路由（manifest、context、empty-classrooms、full-day-status），函数内部按路径分发；对外保持四个 RESTful 路径，打包时共享同一份当前学期数据索引，避免每个函数重复打包。
- Vercel 数据打包通过 `vercel.json` 的 `functions.includeFiles` 明确包含 `data/**`；函数运行时用 `fs.readFileSync` 读取并做模块级内存缓存，不把全部 JSON 静态内联进 bundle，也不在请求时访问 GitHub。
- 自动发布前执行 `git fetch` 与 `pull --ff-only` 更新到最新基线；发布阶段在推送前再次确认远端没有新提交，有则终止并通知，下一轮重试；禁止 force-push 和自动 rebase 解决冲突。

## 9. 快照模型

- 一个教学周一个总 JSON，不使用 JSONL，不按天、房间或小节拆成大量文件。
- 建议路径：

```text
data/terms/<term>/weeks/week-02.json
```

- 内部层级固定为：

```text
week → day → rooms[] → room.status[node]
```

- 房间对象包含 `jsbh`、稳定的 `group_id`、标准化 `name` 和展开后的 01—12 小节状态。
- 状态保存整数状态 ID，不重复保存状态名称、颜色或描述。
- manifest 保存集中状态字典、节次来源映射、公开分组列表和逐周发布索引；状态字典只包含稳定 `id`、`name`、`available`，颜色与图标等视觉映射固定在前端代码，不随数据发布。
- 快照和 manifest 必须包含整数 `schema_version`。Vercel API 只读取当前支持版本；版本不匹配时构建失败，不在运行时迁移。Schema 升级时由采集器重新生成当前学期全部数据。
- 周快照仍按房间平铺；`group_id` 只是房间元数据和筛选索引，不改变同层存储结构。
- 每个周文件保存独立 `snapshot_id` 和 `last_success_at`。API 根据当前北京时间、周次类别、`last_success_at` 和 manifest 中最近尝试结果动态计算 `stale`：最近一次采集失败或超过对应时间阈值，任一成立即为过期；不能依赖采集器写死的布尔值。
- 即使房间状态内容未变化，只要目标周采集成功，也生成新的 `snapshot_id`、更新 `last_success_at` 并正常提交部署。
- 示例：

```json
{
  "schema_version": 1,
  "term": "2025-2026-3",
  "week": 2,
  "snapshot_id": "20260903T041000+0800-week-02",
  "generated_at": "2026-09-03T04:10:00+08:00",
  "last_success_at": "2026-09-03T04:10:00+08:00",
  "days": {
    "1": {
      "rooms": [
        {
          "jsbh": "0899",
          "group_id": "f",
          "name": "F126",
          "status": {
            "01": 5,
            "02": 5,
            "03": 1
          }
        }
      ]
    }
  }
}
```

- 节次来源映射集中放入 manifest，例如：

```json
{
  "nodes": [
    {"code": "01", "source_block": "0102"},
    {"code": "02", "source_block": "0102"},
    {"code": "03", "source_block": "030405"}
  ]
}
```

- 依赖业务不变量把大节状态复制到对应小节；不为每种起止组合单独采集或存储。
- 所有公开房间按同一平面层级保存，不在快照中按建筑或分组拆分。

## 10. Manifest 与当前日期上下文

- `GET /api/v1/manifest` 返回：
  - 数据/schema 版本；
  - 当前公开学期；
  - 可用周次；
  - 公开查询分组及每组房间数；
  - 01—12 节定义及 `source_block`；
  - 状态字典；
  - 生成时间、新鲜度和 stale 状态；
  - 不返回完整房间列表或状态矩阵。
- 采集器把以下日历锚点写入 manifest：

```json
{
  "term": "2025-2026-3",
  "anchor_date": "2026-09-03",
  "anchor_week": 2,
  "total_weeks": 4,
  "timezone": "Asia/Shanghai",
  "in_teaching_calendar": true
}
```

- Vercel API 按 `Asia/Shanghai` 和锚点计算当前周次、星期和日期，不依赖 Vercel 运行区域或用户设备时区。
- 两次采集之间 API 默认按北京时间周一 `00:00` 换周；每天 `04:10` 刷新锚点后若与教务系统返回不一致，以教务系统为准自动修正。
- `GET /api/v1/context` 返回当前日期、当前学期、当前周次、星期和是否处于教学周。
- 当前日期无法映射到有效教学周时，不伪造第 1 周或最近周；前端显示“当前不在教学周内”，仍允许用户手动选择已发布周次。

## 11. 查询 API

- 查询接口全部使用 GET，允许重新设计旧 API，不保留查询型 POST 兼容层。
- 正式资源路由：

```text
GET /api/v1/manifest
GET /api/v1/context
GET /api/v1/empty-classrooms
GET /api/v1/full-day-status
```

### 11.1 空教室查询

- 查询参数：
  - `group_id`：必填，只接受 manifest 中启用的公开分组；
  - `keyword`：可选，只在该分组的已发布房间名称中做普通子串匹配；先去除首尾空格并执行 Unicode NFKC 规范化，ASCII 字母不区分大小写，最长 32 个字符，不支持正则表达式；
  - `week`：可选，省略时使用当前上下文；
  - `day`：可选，省略时使用当前上下文；
  - `start_node`：可选，默认 `01`；
  - `end_node`：可选，默认 `12`。
- API 在所选星期内，对分组内名称匹配的每个房间检查 `start_node..end_node` 的所有小节；全部状态可用才返回。
- 对外房间资源使用 `id` 表示内部 `jsbh`，同时返回标准化 `name`，不返回容量。
- 未收录分组或数据范围返回明确的 `not_collected`；有效分组内没有匹配房间或没有空教室时返回正常空集合。

### 11.2 全天状态查询

- 查询参数：
  - `group_id`：必填，只接受 manifest 中启用的公开分组；
  - `keyword`：可选，只过滤该分组内已发布房间；
  - `week`：可选，省略时使用当前上下文；
  - `day`：可选，省略时使用当前上下文。
- 默认返回匹配房间在该日 01—12 小节的状态。
- 房间状态使用 `statuses: {"01": 5, ...}` 键值结构返回，与周快照存储一致；前端按 manifest 中 `nodes` 顺序渲染。
- 前端默认显示 12 个小节，也允许按 5 个来源大节折叠展示。
### 11.3 API 响应与缓存

- API 使用资源导向的 RESTful 返回结构：成功响应直接返回具体资源，不套统一 `{data: ...}` 外壳；查询响应直接包含 `query`、`rooms` 或状态资源，以及 `snapshot`。
- 错误响应采用 RFC 9457 `application/problem+json`，使用 `type`、`title`、`status`、`detail`、`instance`，并增加稳定的项目扩展字段 `code`。
- 参数格式或范围错误返回 HTTP `400`；未收录分组或周次返回 `404`；有效查询但没有空教室返回 `200` 和空集合；存在旧快照时返回 `200` 并标记 `stale: true`；没有任何可用快照时返回 `503`。
- 数据过期时仍返回最近成功数据，并包含生成时间和最近成功时间。
- 数据接口使用 `Cache-Control: public, s-maxage=300, stale-while-revalidate=600`；日期 context 最多缓存 60 秒；缓存键由完整 GET URL 决定。
- 第一版不分页。房间按名称自然排序，名称相同时按 `jsbh` 排序。
- API 始终分别返回同名不同 `jsbh` 的房间；不合并同名记录。
- 第一版不实现函数内内存限流，也不引入 Redis；依靠严格参数校验、CDN 缓存和 Vercel 平台防护，出现实际滥用后再配置 WAF。
- 第一版不持久化用户查询、IP 或 User-Agent，仅使用 Vercel 提供的聚合运行指标。

## 12. 前端行为

- 技术栈：Vue 3 + Vite + Vant 4。
- 视觉基线沿用旧版 `DESIGN.md` 的品牌色 `#884F22`、Vant 4 主题变量和移动优先布局，仅按新信息架构调整页面结构。
- 第一版正式页面仅包含首页、空教室查询、全天状态查询和基础 404 页面；不恢复数据大屏、公告或管理后台。
- 前端从 manifest 获取公开查询分组、可用周次、节次和状态定义，不硬编码第二份分组名单。
- 空教室页面：
  - 使用 manifest 分组下拉框，`group_id` 必填；
  - 提供可选关键词，只过滤所选分组内房间；
  - 可选择周次、星期、起始节次和终止节次；
  - 节次默认 `01—12`。
- 全天状态页面：使用分组下拉框，并提供可选关键词、周次和星期。
- 页面打开时请求 context，自动填入当前周次和星期，但不默认选择分组，也不自动发起查询。
- 提供明确的“查询”按钮；字段变化只更新表单，Enter 可触发同一查询动作。
- 提供“今天”按钮，用户修改条件后可一键恢复当前周次和星期。
- API 使用北京时间当前上下文补全省略的周次、星期和默认节次；`group_id` 省略时返回参数错误。
- 当前不在教学周时不自动填充周次，显示明确提示，允许手动查询已发布周次。
- 必须区分：
  - 有效分组或关键词范围内没有空教室；
  - 分组或当前数据范围尚未收录；
  - 数据已过期；
  - 当前不在教学周。
- 同一结果中出现同名房间时，前端只对重名项追加缩短后的 `id` 以便区分；其他房间只显示名称。

## 13. 采集告警与本地状态

- 采集器以非零退出码报告失败，并写结构化本地日志。
- 支持通过环境变量配置飞书自定义机器人 Webhook 和签名密钥；请求必须按飞书加签规则生成时间戳和签名。
- 重试耗尽后的最终失败、数据异常被校验拦截、新学期自动切换、连续失败后的首次恢复成功需要发送飞书通知；普通成功不通知。
- 告警内容不得包含账号、密码、Cookie、Token、验证码、原始 HTML 或完整敏感响应。
- 采集状态保存在仓库外的 `~/.local/state/easy-qfnu-kjs/collector-state.json`，使用权限受限文件并通过原子替换写入。
- 同一轮同类错误只通知一次；飞书 Webhook 最多尝试 3 次；只有从失败状态恢复后的首次成功才发送恢复通知。
- Vercel 构建时生成静态 TypeScript 数据索引，显式映射当前学期周次到 JSON；只打包当前学期数据，未压缩函数数据包超过 200 MB 时构建失败。

## 14. 明确废弃的设计

- 不维护官方建筑目录或全校建筑主数据。
- 不上传全量 2079 条原始数据。
- 不按教学楼逐个请求作为默认采集路线。
- 不为 `02—03`、`06—08` 等起止组合分别采集或保存范围文件。
- 不按 12 个小节额外请求 12 次；使用一次周查询的 5 个大节展开。
- 不使用 JSONL 作为正式周快照格式。
- 不让浏览器直接读取 `data/*.json`。
- 不在 Vercel 请求时读取 GitHub 或教务系统。
- 不保留两套正式在线后端。
- 不通过 CORS 提供安全边界。
- 不把未知状态映射为空闲。
- 不采集和公开课程、教师等详情。
- 不把查询分组当作官方建筑主数据，也不按分组嵌套或拆分周快照；房间仍同等级平铺，`group_id` 仅用于白名单归属和查询筛选。
- 不允许省略 `group_id` 后查询全体公开房间；查询必须受公开分组边界限制。

## 15. 安全约束

- 用户提供的教务凭据仅用于经授权的临时探测，不写入本文、仓库、快照、日志或 Vercel。
- 原始 HTML、Cookie、Token、验证码和 OCR 中间数据不得提交或发布。
- Git 提交前应扫描生成目录，确保只包含白名单房间的脱敏快照和公开 manifest。
- Q120—Q127 全部按推荐确认：分组规则支持明确包含/排除但不支持正则；分组 ID 稳定；API 集合字段使用 `rooms`，外部房间字段使用 `id`；页面不默认选择分组，使用明确查询按钮；采集器采用分阶段子命令并支持 dry-run；校验成功后直接推送 `main`；新系统验收后再切换域名和归档旧系统。
